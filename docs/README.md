# Project documentation index

Read in this order when starting a new task:

1. [`PROJECT_CONTEXT.md`](PROJECT_CONTEXT.md) — product objective, principles,
   and source-of-truth hierarchy.
2. [`PROJECT_STATUS.md`](PROJECT_STATUS.md) — dated implementation snapshot,
   tests, and open verification items.
3. [`ARCHITECTURE.md`](ARCHITECTURE.md) — current code and runtime map.
4. [`DECISIONS.md`](DECISIONS.md) — durable product and technical choices.
5. [`../specs/README.md`](../specs/README.md) — accounting and compliance specs,
   with their status and clean-room guidance.
6. [`NEXUS_LONG_HORIZON_PLAN.md`](NEXUS_LONG_HORIZON_PLAN.md) — proposed build
   sequence for obligations, alerts, specialist tasks, verifier reviews, and
   long-term memory.

Keep status facts dated. Update the decision log when a durable decision
changes. Do not copy credentials, customer documents, or private account data
into documentation.
